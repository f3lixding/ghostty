# GObject Integration in Ghostty

## Why This Matters

When reading Ghostty's Linux/GTK code, you'll encounter patterns that seem
"magical" - methods that don't exist in the source, data structures with
mysterious offsets, and compile-time code generation. Understanding GObject is
essential because:

1. **The GTK app is built on GObject**: Every GTK widget in Ghostty (Surface,
   Window, Application) is a GObject class
2. **Private data pattern**: The `self.private()` method you see everywhere
   isn't defined in Ghostty's code - it's generated by the GObject system
3. **Lifecycle management**: GObject handles object creation, reference
   counting, and destruction
4. **Architecture boundary**: GObject is where Zig meets the C-based GTK
   ecosystem

Without understanding GObject, the GTK codebase appears to have missing
functions and unexplained behavior. This document demystifies the system.

## What is GObject?

**GObject is NOT GTK**. It's a separate foundational library that provides an
object-oriented programming system for C.

### The Stack

```
Ghostty Zig Code (src/apprt/gtk/)
  ↓ uses
zig-gobject (Zig bindings)
  ↓ wraps
GObject (C library - object system)
  ↓ used by
GTK (C library - GUI toolkit)
```

### What GObject Provides

- **Type system**: Classes, inheritance, interfaces
- **Properties**: Get/set with change notifications
- **Signals**: Event system (like callbacks)
- **Reference counting**: Automatic memory management
- **Private data**: Encapsulation in C

GTK widgets (buttons, windows, etc.) are all GObject classes. When Ghostty
creates a custom GTK widget, it must follow GObject conventions.

## Defining a GObject Class in Zig

### Example: GhosttySurface

**File**: `src/apprt/gtk/class/surface.zig` (lines 43-54)

```zig
pub const Surface = extern struct {
    const Self = @This();
    parent_instance: Parent,
    pub const Parent = adw.Bin;
    pub const Implements = [_]type{gtk.Scrollable};
    pub const getGObjectType = gobject.ext.defineClass(Self, .{
        .name = "GhosttySurface",
        .instanceInit = &init,
        .classInit = &Class.init,
        .parent_class = &Class.parent,
        .private = .{ .Type = Private, .offset = &Private.offset },
        .implements = &.{
            gobject.ext.implement(gtk.Scrollable, .{}),
        },
    });
```

### What `defineClass` Does

`gobject.ext.defineClass()` is a **compile-time function** that generates code to register your class with GObject's type system.

**Source**: `zig-gobject/src/gobject2/ext.zig` (lines 171-268)

```zig
pub fn defineClass(
    comptime Instance: type,
    comptime options: DefineClassOptions(Instance),
) fn () callconv(.c) gobject.Type {
    // Validation: Instance must be extern struct with Parent
    // ...

    return struct {
        var registered_type: gobject.Type = 0;

        pub fn getGObjectType() callconv(.c) gobject.Type {
            if (glib.Once.initEnter(&registered_type) != 0) {
                // Register type with GObject
                const type_id = gobject.typeRegisterStatic(
                    Instance.Parent.getGObjectType(),
                    options.name orelse deriveTypeName(Instance),
                    &info,
                    options.flags,
                );

                // Allocate private data storage
                if (options.private) |private| {
                    private.offset.* = gobject.typeAddInstancePrivate(
                        type_id, 
                        @sizeOf(private.Type)
                    );
                }

                glib.Once.initLeave(&registered_type, type_id);
            }
            return registered_type;
        }
    }.getGObjectType;
}
```

**What happens**:
1. **Compile time**: `defineClass` generates a `getGObjectType()` function
2. **First call**: Registers the class with GObject, allocates private data space
3. **GObject calculates offset**: Where private data lives relative to instance pointer
4. **Offset stored**: Written to `Private.offset` for later use

## Private Data Pattern

### The Mystery

You see this everywhere in GTK code:

```zig
fn initSurface(self: *Self) !void {
    const priv = self.private();  // ← Where is this defined?
    priv.core_surface = surface;
}
```

But searching for `fn private(` in `surface.zig` finds nothing!

### The Answer

**You write it yourself** as a one-liner using a helper function:

**File**: `src/apprt/gtk/class/surface.zig` (conceptual - not in actual file, but pattern used)

```zig
const Private = struct {
    config: ?*Config = null,
    core_surface: ?*CoreSurface = null,
    size: apprt.SurfaceSize,
    // ... many more fields
    
    var offset: c_int = 0;  // ← GObject writes offset here at runtime
};

// You write this method yourself
fn private(self: *Self) *Private {
    return gobject.ext.impl_helpers.getPrivate(self, Private, Private.offset);
}
```

### How `getPrivate` Works

**Source**: `zig-gobject/src/gobject2/ext.zig` (lines 1566-1577)

```zig
pub const impl_helpers = struct {
    /// Returns a pointer to the private data struct of the given instance.
    pub fn getPrivate(self: *anyopaque, comptime Private: type, offset: c_int) *Private {
        return @ptrFromInt(@intFromPtr(self) +% @as(usize, @bitCast(@as(isize, offset))));
    }
};
```

**It's just pointer arithmetic**:
1. Take the instance pointer (`self`)
2. Add the offset (calculated by GObject)
3. Cast to `*Private`

### Memory Layout

```
┌─────────────────────────────────────┐
│ Public Instance Data                │  ← self (Surface struct)
│ - parent_instance: adw.Bin          │
├─────────────────────────────────────┤
│ [padding/alignment]                 │
├─────────────────────────────────────┤  ← self + offset
│ Private Instance Data               │  ← self.private()
│ - config: ?*Config                  │
│ - core_surface: ?*CoreSurface       │
│ - size: SurfaceSize                 │
│ - cursor_pos: CursorPos             │
│ - ... (many more fields)            │
└─────────────────────────────────────┘
```

GObject allocates this memory as one block. The offset tells you where the private section starts.

## Complete Example

Here's a minimal GObject class showing all the pieces:

**Source**: `zig-gobject/src/gobject2/ext.zig` (lines 271-318) - Test code

```zig
const Subclass = extern struct {
    parent_instance: Parent,

    pub const Parent = gobject.Object;
    const Self = @This();

    // Private data definition
    const Private = struct {
        some_value: i32,
        var offset: c_int = 0;  // GObject writes offset here
    };

    // Register with GObject
    pub const getGObjectType = gobject.ext.defineClass(Self, .{
        .instanceInit = &init,
        .private = .{ .Type = Private, .offset = &Private.offset },
    });

    // Constructor
    pub fn new() *Self {
        return gobject.ext.newInstance(Self, .{});
    }

    // Lifecycle callback
    fn init(self: *Self, _: *Self.Class) callconv(.c) void {
        self.private().some_value = 123;
    }

    // Accessor for private data (you write this)
    fn private(self: *Self) *Private {
        return gobject.ext.impl_helpers.getPrivate(self, Private, Private.offset);
    }

    // Public method
    pub fn getSomeValue(self: *Self) i32 {
        return self.private().some_value;
    }

    // Class struct (required by GObject)
    pub const Class = extern struct {
        parent_class: Parent.Class,
        pub const Instance = Self;
    };
};

// Usage
const obj = Subclass.new();
defer obj.unref();
const value = obj.getSomeValue();  // Returns 123
```

## Why This Architecture?

### GObject's Design Goals

1. **Object-oriented C**: C has no native OOP, so GObject provides it
2. **Language bindings**: Python, JavaScript, Rust can all use GObject classes
3. **ABI stability**: Private data can change without breaking binary compatibility
4. **Introspection**: Tools can discover class structure at runtime

### Why Ghostty Uses It

1. **GTK requirement**: To create custom GTK widgets, you must use GObject
2. **Native integration**: Ghostty's GTK app looks and behaves like a native GNOME app
3. **Ecosystem access**: Can use any GTK/GNOME library

### 1. Accessing Private Data

### 4. Lifecycle Callbacks

```zig
fn init(self: *Self, _: *Class) callconv(.c) void {
    // Called when instance is created
    const priv = self.private();
    priv.focused = true;
    priv.size = .{ .width = 0, .height = 0 };
}

fn dispose(self: *Self) callconv(.c) void {
    // Called when instance is being destroyed
    const priv = self.private();
    if (priv.config) |v| {
        v.unref();
        priv.config = null;
    }
}
```

## Key Takeaways

1. **GObject ≠ GTK**: GObject is the object system, GTK is the GUI toolkit built on it

2. **`defineClass` is compile-time magic**: It generates the boilerplate to register your class with GObject

3. **`private()` is not auto-generated**: You write it yourself as a one-liner using `impl_helpers.getPrivate()`

4. **Private data is pointer arithmetic**: `self + offset` where offset is calculated by GObject at runtime

5. **Memory layout is controlled by GObject**: Public instance data, then private data in one allocation

6. **This is Linux/GTK specific**: The macOS app doesn't use GObject at all (it uses Swift/Objective-C)

## Debugging Tips

### Finding Private Data

When you see `priv.some_field`, search for:
```zig
const Private = struct {
```

### Finding Methods

GObject methods are regular Zig functions. Search for:
```zig
fn methodName(self: *Self, ...)
```

### Understanding Signals

When you see `Surface.signals.bell.impl.emit(...)`, look for:
```zig
pub const signals = struct {
    pub const bell = struct {
```

### Tracing Lifecycle

Look for these callbacks:
- `init` - Instance creation
- `dispose` - Instance destruction (cleanup refs)
- `finalize` - Final cleanup (free memory)
- `classInit` - Class initialization (once per type)
